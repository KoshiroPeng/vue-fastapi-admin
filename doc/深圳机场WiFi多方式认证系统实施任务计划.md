# 深圳机场 WiFi 多方式认证系统实施任务计划

> 依据：《深圳机场WiFi多方式认证系统详细设计说明书》
>
> 适用对象：产品负责人、技术负责人、后端/前端开发、测试、网络与 NCE 联调人员、运维与安全人员
>
> 计划目标：将当前 `vue-fastapi-admin` 管理框架演进为“旅客 Portal 认证前置网关 + 机场 WiFi 运维管理台”，并完成短信、护照、登机牌、微信小程序、现场取号机五种认证方式的端到端交付。

## 1. 分析结论

### 1.1 项目本质

本项目不是普通后台换皮，而是由三个交付面组成的集成系统：

1. **旅客端 Portal H5**：在 Captive Portal、普通手机浏览器、微信内置浏览器中提供五种认证入口及状态反馈；
2. **FastAPI 认证前置网关**：负责 Portal 参数解析、短时认证事务、风控、第三方协议适配和 NCE 访客创建；
3. **运维管理台**：复用现有用户、角色、菜单和 API 权限，实时代理 NCE 数据并展示统计、在线用户、准入日志、依赖健康度和只读配置摘要。

准入控制权始终属于华为 iMaster NCE-Campus。本系统不能把“第三方校验成功”“接口请求成功”误判成“终端已联网”。

### 1.2 当前代码基础

当前仓库已经具备：

- FastAPI、Tortoise ORM、Aerich、Pydantic Settings 基础框架；
- 管理员登录、JWT、用户、角色、菜单、部门、API 路径权限；
- 管理员操作审计；
- Vue 3、Naive UI、Pinia、Vue Router、动态菜单和通用 CRUD 组件；
- SQLite 开发数据库、Dockerfile、Nginx 示例配置。

当前仓库尚不具备：

- Redis 客户端、认证事务、Nonce 防重放和分布式限流；
- NCE、登机牌、OCR、微信回写、取号机客户端或服务；
- 旅客 Portal 页面及独立布局；
- WiFi 运营看板、在线用户、RADIUS 日志、健康监控、运行配置摘要；
- 第三方调用摘要表及清理任务；
- ECharts 等图表依赖；
- 自动化测试体系、外部系统 Mock、Postman 联调集合；
- Docker Compose、Redis、生产数据库和多实例部署编排。

因此，当前状态应判断为：**管理后台脚手架可复用，但 WiFi 业务能力基本尚未实现。**

## 3. 原设计中需修正或补充的风险

### 3.1 高优先级设计风险

1. **护照“零落盘”与 `UploadFile` 存在冲突**：Starlette/FastAPI 的上传实现通常使用 `SpooledTemporaryFile`，超过内存阈值可能自动写临时磁盘。必须采用受控流式读取或明确调整并验证 spool 阈值，不能仅凭“使用 UploadFile”宣称零落盘。
2. **临时密码返回方式不一致**：设计一处描述返回一次性 `txToken`，接口示例却直接返回 `tempPassword`。建议统一为不透明的一次性事务凭据；若受 NCE Portal 限制必须把密码交给浏览器，则只在内存中短时存在、禁止 URL/日志/持久化，并在成功或失败后主动清除。
3. **微信成功状态证据不足**：签名回写只能证明“可信小程序发来了结果”，不能天然证明 NCE 已放行。需约定 NCE 成功凭证、回调载荷或可查询证据，并据此更新 `SUCCESS`。
4. **SQLite 与双实例部署冲突**：两个 FastAPI 实例不能各自使用本地 SQLite 作为共享管理数据库。SQLite 仅限开发/单机；生产高可用必须使用共享数据库。
5. **统计实现可能成本过高**：通过实时翻页拉取全天 RADIUS 日志计算趋势和成功率，在大客流下可能超时或压垮 NCE。优先使用 NCE 聚合接口；若只能查询明细，应增加短时聚合缓存、查询窗口限制、并发合并和熔断。
6. **认证方式分布口径不充分**：`userTypeCode=20` 无法区分登机牌、护照和取号机。必须验证 NCE 日志是否返回用户名/描述，并使用受控前缀；否则只能展示“普通访客”，不能虚构五类精确占比。

### 3.2 当前代码必须先处理的安全风险

1. 当前存在 `token == "dev"` 的鉴权旁路，生产环境必须禁用或删除；
2. 当前默认创建 `admin/123456`，必须改为首次部署注入、强制修改或一次性初始化；
3. 当前 `SECRET_KEY` 硬编码，必须改为生产必填 Secret；
4. 当前 CORS 为 `*` 且允许凭据，应拆分管理台、Portal 和回写接口的来源策略；
5. 当前审计中间件会保存请求体和响应体，可能落库保存证件尾号、手机号、访客密码或回调载荷；Portal、取号机和第三方回写接口必须排除原文审计，并使用白名单式脱敏摘要；
6. 当前路径权限为“HTTP 方法 + 精确路径”，详细设计中的 `wifi:dashboard:view` 等权限点并非现有模型能力。首期建议沿用现有路径权限，菜单名称作为业务权限标签；若必须支持权限代码，应单独扩展数据模型和鉴权器。

## 4. 实施原则

1. **先打通最不确定的真实链路，再铺开页面**：优先验证 NCE Token、创建访客、Portal 提交和 Captive Portal 兼容性；
2. **按端到端垂直切片交付**：每个认证方式都包含页面、API、第三方客户端、事务状态、安全控制、Mock 和自动化测试；
3. **外部系统未就绪时使用契约 Mock，但不把 Mock 通过视为联调完成**；
4. **默认拒绝、最少采集、禁止敏感信息持久化**；
5. **所有外部调用具有超时、有限重试、幂等、熔断、脱敏日志和 traceId**；
6. **旅客端公开接口与管理台 JWT 接口分开鉴权和限流**；
7. **生产发布以可回滚、可观测、可灰度为前提**。

## 5. 详细任务清单

> 工作量为初步人日估算，不含外部团队排期和等待时间。建议由 2 名后端、1 名 Portal/前端、1 名测试兼联调、0.5 名运维/安全共同实施。

### 阶段 A：契约冻结与工程基线

#### T-001 外部接口契约与真实链路预研

- **工作量**：4～7 人日
- **依赖**：无
- **风险**：高
- **任务**：完成 D-01～D-08；建立脱敏 Postman 集合；保存真实成功/失败报文样例；确认 NCE 端口、TLS、证书、网络白名单和时钟同步。
- **交付物**：接口契约基线、测试变量模板、签名测试向量、Portal 抓包说明、兼容性初测结论。
- **验收**：NCE Token、创建访客、RADIUS 查询和至少一种真实 Portal 准入链路通过。

#### T-002 测试与 CI 基线

- **工作量**：2～3 人日
- **依赖**：无
- **风险**：中
- **任务**：引入后端测试框架、异步测试客户端、覆盖率；引入前端单元测试；配置 lint、单测、构建流水线；测试使用独立数据库和 Redis。
- **验收**：空白基线在 CI 中稳定执行；失败测试能阻断合并；生成覆盖率报告。

#### T-003 配置与现有安全基线加固

- **工作量**：3～5 人日
- **依赖**：T-002
- **风险**：高
- **任务**：移除生产鉴权旁路和默认弱口令；密钥改为环境注入；收紧 CORS；增加可信代理/IP 获取规则；重构审计日志为字段白名单与脱敏策略；定义 Portal 免 JWT 路由和管理台受保护路由边界。
- **验收**：生产配置缺少关键 Secret 时启动失败；敏感字段不会进入审计表或应用日志；普通角色不能访问未授权 API。

### 阶段 B：认证公共底座与 NCE 能力

#### T-004 Redis、认证事务与防重放闭环

- **工作量**：4～6 人日
- **依赖**：T-002、T-003
- **风险**：高
- **任务**：实现 Redis 生命周期管理、`authTxId` 状态机、TTL、一次性消费、Nonce、防重放、IP/MAC 哈希、滑动窗口限流和统一错误响应。
- **验收**：`INIT → PENDING → SUCCESS/FAILED/EXPIRED` 可测试；重复消费返回 409；过期返回 404；限流返回 429；Redis 不出现明文 MAC、密码、证件信息。

#### T-005 NCE 客户端与 Token 管理

- **工作量**：5～8 人日
- **依赖**：T-001、T-004
- **风险**：高
- **任务**：实现异步连接池、Token 获取/共享/提前刷新、并发刷新锁、401 单次重试、访客创建、用户查询、RADIUS 日志查询、在线用户查询、标准错误映射、健康探测和 Mock。
- **验收**：多并发请求只触发一次 Token 刷新；Token 失效后业务请求自动恢复；所有日志中无 Token 和访客密码；契约测试覆盖主要返回码。

#### T-006 Portal 壳、参数解析与状态页

- **工作量**：5～7 人日
- **依赖**：T-004
- **风险**：高
- **任务**：新增不依赖管理台 Layout 的移动端入口；解析并服务端校验 `wlanuserip`、`wlanusermac`、`ssid`、`siteId`、`redirectUrl`；实现认证方式开关、状态机、失败重试、维护态、成功页和安全跳转白名单。
- **验收**：缺少关键参数时明确提示；开放重定向测试失败；手机竖屏、微信浏览器、iOS/Android Portal 基础展示通过；按钮不可重复提交。

- **验收**：真实 `state/code/pushPageId` 完成 NCE 放行后页面成功；伪造、过期、重放回调被拒；未取得 NCE 成功证据不得进入 `SUCCESS`。

#### T-011 现场取号机认证端到端切片

## 8. 测试与验收矩阵

### 8.1 后端自动化

- 认证事务状态机、TTL、一次性消费、幂等；
- Token 并发刷新和失效重试；
- HMAC、时间戳、Nonce、防重放；
- 滑动窗口限流和冷却恢复；
- 登机牌/OCR/NCE/微信错误码映射；
- 文件大小、MIME、魔数和零落盘验证；
- 脱敏函数、审计排除和 Secret 泄漏扫描；
- RADIUS 游标分页和统计口径。

### 8.2 前端自动化与兼容性

- Portal 参数缺失、输入、上传、识别、认证、等待回写、成功、失败、维护状态；
- 重复点击、弱网、轮询超时、返回页面、刷新和事务过期；
- 手机浏览器、微信浏览器、iOS CNA、Android Captive Portal；
- 管理台角色菜单、无权限访问、脱敏列表和故障态。

### 8.3 安全专项

- 开放重定向、伪造来源 IP、CORS、CSRF/回调伪造；
- HMAC 篡改、时间戳过期、Nonce 重放；
- 登机牌三要素枚举、OCR 资源消耗、超大文件和压缩炸弹；
- 日志、数据库、Redis、浏览器控制台和网络响应中的 PII/凭据泄漏；
- 默认账号、弱口令、硬编码 Secret、Mock 误开生产。

### 8.4 性能与故障注入

- 峰值认证 QPS、并发图片上传、管理台大时间窗查询；
- NCE/OCR/登机牌接口慢响应、超时、断网、错误码风暴；
- Redis 短暂不可用、数据库不可用、单应用实例退出；
- Token 集中过期时的惊群控制；
- 熔断打开、半开、恢复和页面认证方式降级。

## 10. 项目完成定义

只有同时满足以下条件，项目才可视为完成：

1. 五种认证方式均使用真实外部系统完成端到端网络准入；
2. 管理台统计、在线用户和 RADIUS 日志来自 NCE 或明确标注的数据源；
3. 本地数据库不存在旅客业务明细，Redis 中敏感短时状态按 TTL 自动删除；
4. 日志、审计表、浏览器和接口响应中无 Token、验证码、护照图像、完整证件号、访客密码等泄漏；
5. 权限、限流、防重放、幂等、超时、重试、熔断和降级均有自动化或故障注入证据；
6. 真实终端兼容、性能、安全、双实例故障切换和回滚演练通过；
7. 生产 Mock 已关闭，全部 Secret 由受控环境注入；
8. 上线检查清单、运维手册和责任人签字齐备。
